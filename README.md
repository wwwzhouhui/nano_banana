# 🍌 Nano Banana OpenRouter Text-to-Image Plugin

> High-quality AI text-to-image Dify plugin based on OpenRouter API, supporting multiple advanced image generation models

## ✨ Features

- 🎨 **Multi-Model Support**: Supports OpenRouter image preview models such as Google Gemini image models
- 📝 **Text-to-Image Ready**: Works with prompt-only generation without requiring any image input
- 🔄 **Image-to-Image Support**: Supports image transformation using a Dify file input or a real public image URL
- 🧠 **Safer Input Handling**: Automatically ignores placeholder-style workflow variables like `1756601479774.picture.url` when no real image is provided
- 🖼️ **Robust Image Output Parsing**: Supports OpenRouter responses from both `message.images[*].image_url.url` and segmented `message.content[*].image_url.url`
- 🌐 **Multilingual**: Complete bilingual support in Chinese and English
- ⚡ **Real-time Feedback**: Detailed generation progress and status feedback
- 🛡️ **Error Handling**: Comprehensive error handling with user-friendly prompts

## 🚀 Quick Start

### 1. Get OpenRouter API Key

1. Visit [OpenRouter](https://openrouter.ai/keys)
2. Create an account and generate an API Key
3. Copy your API Key (format: `sk-or-v1-xxxxxx`)

### 2. Install Dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure Environment Variables

```bash
# Copy environment template
cp .env.example .env

# Edit .env file and add your API Key
OPENROUTER_API_KEY=sk-or-v1-your-api-key-here
```

### 4. Test Plugin

```bash
# Test API connection
python tests/test_openrouter_api.py

# Test full plugin functionality
python tests/test_plugin.py
```

## 🎯 Supported Models

### Built-in Models
- **Google Gemini 3.1 Flash Image Preview** (`google/gemini-3.1-flash-image-preview`): Fast default choice for most text-to-image and image-to-image tasks
- **Google Gemini 3 Pro Image Preview** (`google/gemini-3-pro-image-preview`): Higher-quality option when you want better image fidelity

### Manual Model Override
- You can optionally fill in `model_manual` to use any compatible OpenRouter model ID
- When `model_manual` is provided, it overrides the dropdown selection

## 📖 Usage Examples

### Input Modes

#### 1. Prompt-only generation
Leave both `input_image` and `input_image_url` empty. The plugin will send only the text prompt to OpenRouter.

#### 2. Image-to-image with Dify file input (recommended)
Bind a workflow file/image variable to `input_image`. This is the preferred mode in Dify workflows.

#### 3. Image-to-image with public URL fallback
If you already have a real public image URL, pass it through `input_image_url`.

### Notes about optional image input

- `input_image` has higher priority than `input_image_url`
- `input_image_url` only accepts real `http(s)` URLs or `data:image/...` URLs
- Placeholder-style values generated by workflow binding, such as `1756601479774.picture.url`, are treated as "no image provided" when there is no actual uploaded image
- Generated images returned by OpenRouter are parsed from both `message.images` and segmented `message.content`

## 🔧 Configuration Guide

### API Key Configuration
- Enter your OpenRouter API Key in the Dify plugin configuration
- Ensure the API Key format is correct (`sk-or-v1-xxxxxx`)
- Confirm your account has sufficient balance for the model you selected

### Image Input Configuration
- Prefer `input_image` for Dify workflow uploads and upstream image outputs
- Use `input_image_url` only when you have a real public image URL or a `data:image/...` URL
- Do not manually pass workflow placeholder strings as image URLs

### Model Selection Recommendations
- **Default / fast iteration**: Use `Google Gemini 3.1 Flash Image Preview`
- **Higher quality output**: Use `Google Gemini 3 Pro Image Preview`
- **Custom OpenRouter model**: Fill in `model_manual` when you need a model that is not listed in the dropdown

## 🐛 Troubleshooting

### Common Issues

1. **Invalid API Key**
   - Check if the API Key format is correct
   - Confirm the API Key hasn't expired
   - Verify account status

2. **Insufficient Balance**
   - Go to [OpenRouter Credits](https://openrouter.ai/credits) to recharge
   - Use free models for testing

3. **Generation Failure**
   - Check whether the prompt contains sensitive content
   - Try switching models
   - Simplify the prompt
   - If you are using image-to-image, prefer `input_image` over `input_image_url`

4. **Image Input Not Taking Effect**
   - Make sure the workflow binds the uploaded image to `input_image`
   - If `input_image_url` contains a placeholder value instead of a real URL, the plugin will ignore it and continue with prompt-only generation
   - If you need URL-based image input, provide a real public `http(s)` URL or `data:image/...`

5. **Network Issues**
   - Check network connection
   - Confirm firewall settings
   - Try again later
